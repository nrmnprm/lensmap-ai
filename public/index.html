Ask where to go, what is on tonight or where the nearest pharmacy is. The advisor may only recommend places and events that exist in the data on the map, and every answer can be inspected.

Posts as the crawler collected them on the morning of the demo date. Free text goes to the model; the ticketing page carries schema.org markup and is parsed without it. Coordinates always come from map data. You can edit any post.

How it works

Advisor. For every question the server builds a context from the bundled OpenStreetMap snapshot and the event list: places near you (by category for specific questions, a varied set for general ones), opening hours evaluated at the demo clock, the weather and events of the next 48 hours. The model may recommend only items from that context and must return their ids. The server then drops ids that are not in the context, attaches places the model named but forgot to cite, hides cards for items the answer never mentions, and orders the cards as they appear in the text. An answer in the wrong language or script is retried once, then replaced by a template.

Extraction. Posts are batched (8 per model call) and cached by a hash of their content. The model returns title, date, time, venue and district; the server checks the date against the weekday the post names, validates the 21-day window, geocodes the venue against the map data and falls back to a landmark, the district or the city centre, marking such points as approximate.

Without an API key recorded answers are replayed for exactly the same requests; anything else is answered from a template over the same context.
